Discovery. Anti-duplication. None of today's identifiers or titles appeared in the archive. Prior briefings covered harness qualification, evaluation contracts, process completion, evidence provenance, benchmark suitability, and persistent-state acceptance. Today's incremental question is operationally sharper: when an agent underperforms, is the missing ingredient more autonomy, or a better information interface, candidate pool, executable verifier, and process contract?

Evidence labels. Paper Fact is directly reported in a paper or verified first-party artifact. Independent Analysis is this briefing's comparison, calculation, or methodological judgment. Enterprise Inference translates evidence into a bounded future option. Uncertainty marks missing causal, external-validity, security, privacy, governance, economic, adoption, artifact, or licensing evidence. Provider-scale experiments were not rerun. No benchmark result authorizes production deployment.

Executive signal

More autonomy is not a substitute for better information, candidate coverage, or executable process contracts. Agentic effort becomes useful only after the system exposes the right task state and verifies the trajectory that produced the answer.

The three deep papers triangulate this claim:

  1. Agents Are Systems, Not Models varies five configuration axes across 8,640 main runs on four scientific tasks. About 54% of genuine-attempt score variance is within identical configurations. Information has the largest effect on every scored task; prompting verification ranks last, while a dedicated verification tool materially changes behavior.
  2. ScholarCatalyst asks 184 lead authors of 207 recent computer-science papers which prior work did or could have advanced their project. On 894 questions against a 191K-paper temporally restricted corpus, agentic search does not beat dense retrieval because useful papers frequently never enter the candidate pool.
  3. Continuous Process-Level Evaluation evaluates 240 runs of two enterprise agent skills. Among 175 runs passing every applicable final numerical check, 162 still contain another evaluator-detected deviation; even a broader seven-check final state misses trajectory violations in 151 of 164 passing runs.

The Watchlist sharpens two architectural boundaries. VISTA reports large gains from lossless visual memory and inspection tools, but only on public benchmarks that may have appeared in model training. Code Owns the Simulation separates consequence generation from option evaluation, but tests one judgment model and relies on exact environment copies or tuned skills.

Decision posture. Prototype configuration-aware repeated-run qualification, process-contract regression gates, and candidate-coverage diagnostics. Prepare task-information contracts, trace/root-cause observability, and temporally valid evidence provenance. Monitor lossless multimodal memory and simulator/evaluator splits until private, representative, adversarial, privacy, and economic evidence matures. Deprioritize prompt-only verification, indiscriminate extra time, and agentic search without baseline comparison.

Deep paper 1 — The evaluated unit is a configuration distribution, not a model

Identity and status. Agents Are Systems, Not Models: Rethinking Agentic Evaluation; Luis Wiedmann, Leander Girrbach, Cordelia Schmid, and Zeynep Akata; arXiv:2610.01618v1; submitted October 1, 2026 at 12:55:07 UTC; preprint; paper licensed CC BY 4.0. The verified repository links 18,240 trajectories on Hugging Face but says full code and benchmark are “coming soon.” (paper · repository · trajectories)

Contribution and quantitative claim trace

The benchmark requires a coding agent to locate and operate specialist models for four astrophysics/genomics tasks. The main factorial grid varies information, reasoning, prompted verification, runtime budget, and backbone model: 432 cells per task, five repetitions, 8,640 main runs. Additional ablations bring the released trajectory count to 18,240.

Methodological critique and prior-work comparison

Most agent leaderboards compare fixed scaffolds or backbone models. This paper treats the system configuration itself as the object of study and crosses five axes rather than changing one prompt at a time. The repeated-cell design is unusually strong for estimating stochasticity; the hurdle separates trivial non-attempts from conditional score; the paper also reports completion, cost, calibration, and behavior categories rather than one success rate.

The information result is not a pure causal estimate of “documentation quality” outside these tasks. The four levels progress from no extra information to identity, interface, and a full protocol; this combines several mechanisms. The three Qwen backbones are FP8-quantized and the tasks require preselected scientific models in prebuilt environments. Five repeats still leave wide cell-level intervals. Pooling the three positive-gap tasks weights very different metrics through gap normalization. Behavior categories are induced with model-assisted extraction, clustering, and labeling. The oracle ablation supplies privileged reference evaluation and therefore establishes a design principle, not a ready-made production component.

Prior work argues for holistic agent evaluation, reproducibility, and scaffold-aware comparison. This paper advances that line by measuring configuration interactions and within-configuration variance at scale. It does not establish that information will dominate in customer service, security, finance, or open-world computer use.

Reproducibility and enterprise readiness

The paper exposes prompts, task construction, metrics, factorial design, statistical analyses, and a trajectory dataset. The public repository currently has one commit and explicitly defers full code/benchmark release, so exact reruns are not yet turnkey. The paper uses open-weight main backbones but substantial H100-class compute. Enterprise readiness: high for adopting repeated runs, interaction matrices, separate completion/quality/cost reporting, and tool-backed verification; medium for using the released task pattern; low for adopting its effect ordering as a universal capacity-planning rule. Research Utility Score: 95/100 (methodological rigor 25/25; quantitative traceability 25/25; reproducibility/artifacts 17/20; enterprise relevance 14/15; prior-work advance 14/15).

Deep paper 2 — Search intelligence starts with candidate coverage

Identity and status. ScholarCatalyst: A Benchmark for Retrieving Papers That Inspire New Research; Sohyeon Kim and 13 coauthors; arXiv:2610.02202v1; submitted October 1, 2026 at 17:59:47 UTC; 57 pages; preprint; paper licensed CC BY 4.0. The verified project links public code, benchmark instances, annotations, and evaluation scripts; the GitHub repository contains an explicit license file and quick-start instructions. (paper · project · code · data)

Contribution and quantitative claim trace

The benchmark collects retrospective author judgments about prior work that did or could have advanced a project before its solution was known. It contains 207 core research questions and 687 subfield questions from 184 researchers, with positive papers, hard negatives, rationales, and a cutoff corpus restricted to papers available when each project began.

Methodological critique and prior-work comparison

Existing scientific-retrieval benchmarks usually label topical relevance, citation support, or whether a paper cites/extends another. ScholarCatalyst targets a harder and more decision-relevant relation: whether an earlier idea could move an incompletely specified project forward. Direct author validation, rationales, temporal cutoffs, uncited positives, and hard negatives are significant advances over citation-derived gold.

The benchmark is also inherently subjective. Authors label completed projects retrospectively and may not agree with other experts about what “could have” helped. The automated pre-annotation pipeline can shape the candidate set presented for review; incomplete candidate generation may produce false negatives outside the reviewed pool. Projects are recent computer-science work, more than 100 are oral/spotlight/award papers, and field coverage is uneven. The human skyline is unknown because independent domain experts would measure a different target. Post-cutoff models may have seen source papers; the paper separates them for comparison but contamination cannot be ruled out.

The reported “0.42 versus 0.48” aggregate is useful as a headline but hides CoreQ/SubQ differences and model-specific rows. The decision-relevant finding is not that agents never help. It is that an agent cannot recover papers its query policy and retriever never surface, and that stronger reranking pays only after coverage improves.

Reproducibility and enterprise readiness

Public code includes embedding and agentic baselines, evaluation scripts, configuration, requirements, and benchmark download instructions. Public data exposes benchmark instances and annotations; the full 191K corpus may need reconstruction or external scholarly metadata. Provider models, API access, and exact pricing remain external dependencies. Enterprise readiness: high for building expert-judged candidate-coverage tests and baseline-first routing; medium for research/knowledge discovery pilots after domain-expert relabeling and data-rights review; low for autonomous research prioritization. Research Utility Score: 96/100 (methodological rigor 24/25; quantitative traceability 25/25; reproducibility/artifacts 20/20; enterprise relevance 13/15; prior-work advance 14/15).

Deep paper 3 — Final-state correctness does not prove process conformance

Identity and status. Continuous Process-Level Evaluation for Evolving Enterprise AI Agent Skills; Ngoc Phuoc An Vo, Aarya Doshi, and Vadim Sheinin; arXiv:2610.01833v1; submitted October 1, 2026; accepted to the NeurIPS 2026 Workshop on Continual Learning for Enterprise AI Agents; paper licensed CC BY 4.0. No public code, trace dataset, or evaluation suite was linked or independently found. (paper)

Contribution and quantitative claim trace

The authors construct runtime-resolved template tests for two related Business Value Determination skills in an enterprise resiliency system. A separate Python path calls the live APIs to compute expected values; rule-based checks cover structure and trajectory, while a scoped LLM judge handles designated semantically flexible arguments.

Methodological critique and prior-work comparison

Process evaluation, deterministic state contracts, and dependency-aware workflow checking have precedent. The contribution is the combination of live independent ground truth, runtime placeholders, reusable regression templates, and trajectory checks across models, harnesses, and specification revisions in an operationally grounded system.

The paper is unusually explicit about its limits. It studies one enterprise portfolio of nine applications, two related skills, two dates, and ten trials per cell. MD and TXT are not a controlled format treatment; their instructions differ materially. The aggregate suite score mixes heterogeneous checks with unequal operational severity. The independent oracle calls the same live services, so mutable state can differ between agent and evaluator. Many “irrelevant tool” failures are harmless utilities; other checks expose unresolved business-policy assumptions rather than clear defects. The dependency graph labels roots descriptively but does not prove causality.

Execution failures complicate inference. External errors are balanced by harness overall, but unrecovered errors concentrate in Codex runs; excluding them removes all observations from one cell. The intention-to-evaluate view is honest, yet it mixes agent capability, harness resilience, tool availability, and provider behavior. Longitudinal persistence under actual API evolution—the motivation for “continuous”—remains future work.

Reproducibility and enterprise readiness

The paper specifies the 2×2×2×3×10 design, suites, prompts, checks, confidence intervals, and clean-run table, but the real APIs, portfolio, traces, and suite are unavailable. Enterprise readiness: high for the design pattern of independent oracles, typed trajectory invariants, and dependency-linked triage; medium for a pilot on one internal workflow; low for transferring the reported deviation rate or thresholds. Research Utility Score: 88/100 (methodological rigor 23/25; quantitative traceability 25/25; reproducibility/artifacts 10/20; enterprise relevance 15/15; prior-work advance 15/15).

Watchlist

VISTA — lossless visual memory looks powerful, but public-game contamination is unresolved

Identity and status. VISTA: A Visual Harness for Reasoning in an Interactive World; Qiushi Han, Keya Hu, Linlu Qiu, Cathy Wu, and Kaiming He; arXiv:2610.02200v1; submitted October 1, 2026; technical report; paper licensed CC BY 4.0; public GitHub repository linked. (paper · code)

VISTA stores every visual frame in original form and lets the model revisit frames, crop regions, and read pixels. On 25 public ARC-AGI-3 games, the Opus 5.0 system reports RHAE 100.00 with 7,302 actions, 57.4% fewer than the 17,135-action human reference; GPT-5.6 Sol reaches 99.00. Reducing context to 100K changes RHAE by only −0.4 while roughly halving tokens, and 256-pixel inputs use 75% fewer image tokens than 512-pixel inputs with comparable performance. An open GLM-5.3 Flash 320B backend reaches 66.93 and beats the official minimal harness. Results also improve on GameWorld, AI GameStore, and 39 BabyVision tasks.

Why Watchlist, not deep selection. The main results are on public games; the authors explicitly cannot rule out training exposure and call for private-set evaluation. A perfect public score cannot estimate generalization, privacy risk, memory growth, video retention policy, or enterprise economics. The design is nevertheless strategically important: preserve raw evidence outside the model context and give the model selective, auditable re-attention. Promote after private, time-split, repeated-run evaluation with storage/privacy budgets and component ablations.

Code Owns the Simulation — a useful split tested on one judgment model

Identity and status. Code Owns the Simulation, Jev Owns the Evaluation; Yaodong Yang and six coauthors; arXiv:2610.01834v1; submitted October 1, 2026 at 15:06:40 UTC; 20 pages including appendix; preprint; paper licensed CC BY 4.0. No public code or data artifact was linked. (paper)

The paper tests a no-reasoning judgment model on cognitive reflection, matrix games, ALFWorld, and robot control. Jev answers 99% of counterintuitive reflection items, predicts the opponent separately in 90% of misleading games, and chooses correctly in 98% when the correct prediction is supplied, yet gets only 33% when one call must both simulate and decide. In unseen ALFWorld games, Jev alone solves 42/134; next-state text raises this to 79, and next-state plus newly enabled commands to 116/134 (87%). With raw robot torques it solves none of 20 episodes; with code-supplied skills and physics it matches a native controller and improves on new variants.

Why Watchlist, not deep selection. The boundary is clean and experimentally varied, but only one API/model is tested. Exact copies of ALFWorld and the physics environment give privileged simulation unavailable in many enterprise processes; the robot skills are tuned on the native task, and action granularity differs between raw-torque and skill conditions. Promote after multi-model replication, imperfect-world-model tests, uncertainty propagation, and adversarial simulator mismatch.

Independent Analysis. The common result is not “harnesses matter,” which is too broad to guide architecture. It is that each paper localizes a missing state transition. The scientific agent needs an explicit information interface; the search agent needs candidate coverage; the enterprise skill needs a typed process contract; the visual agent needs recoverable original observations; the judgment model needs predicted consequences. Adding model calls before exposing that state can increase completion, latency, and spend without increasing decision quality.

This also changes how an enterprise should interpret autonomy. Autonomy is not a scalar. Search autonomy, runtime autonomy, memory autonomy, and action autonomy rely on different evidence contracts. A system may safely explore more candidates while still requiring deterministic tool arguments, human approval for durable effects, or abstention when a simulator is uncertain. Every proposed enhancement below is therefore a future option conditioned on internal workflow, risk, data, and architecture evidence.

Independent Analysis. Over 12–24 months, the highest-leverage shift is from a model-centric stack to an evidence-bearing control plane around models and agents. This is an architectural option, not an assumption about the current enterprise stack.

The shared sequence should be: identify task and information contract → retrieve evidence with coverage telemetry → execute under typed orchestration → record trajectory and state → verify process and final effect independently → route uncertainty to human review → retain configuration/evidence lineage for replay. Internal workflow values, architecture, identity model, data classifications, regulated-data exposure, retention rules, staffing, and risk tolerance are required before any implementation decision.

Knowledge reinforcement

What should be remembered

  1. The model is not the evaluated unit. Information, tools, budget, harness, and stochastic runs change the outcome.
  2. More time can raise completion while lowering conditional quality. Track both.
  3. An agent cannot reason over a paper, frame, state, or consequence it never receives. Instrument candidate and evidence coverage.
  4. Correct final output does not prove a correct process. Scope, ordering, persistence, and effect need contracts.
  5. Prompted verification is not a verifier. A control needs an executable evidence path.
  6. Root-cause labels and simulator outputs are models too. Version their assumptions and uncertainty.

Questions for the next design review

  1. Which current agent decisions are based on one run, one judge, or one aggregate score?
  2. Where does candidate coverage end and reasoning begin in each retrieval pipeline?
  3. Which workflow invariants are operationally harmful when violated, and which are merely stylistic?
  4. Can final state be computed independently of the agent's own trace and tools?
  5. What raw evidence must remain recoverable, and what privacy/retention constraints forbid keeping it?
  6. Which action domains have a valid simulator, and how is simulator uncertainty escalated?
