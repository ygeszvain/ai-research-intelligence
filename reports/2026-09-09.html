Scope, window, and evidence policy

Research window. Monday, September 7, 2026 at 4:00 PM CDT through Wednesday, September 9, 2026 at 4:00 AM CDT (36 hours; America/Chicago). Discovery covered the new arXiv cs.AI, cs.CL, cs.LG, cs.SE, cs.CR, cs.HC, and stat.ML feed plus targeted checks of current journal, conference, and research-lab releases. The arXiv screen returned 297 records before relevance, evidence, and duplication filtering. The original window was sufficient; no seven-day expansion was used.

Anti-duplication. Exact titles, arXiv identifiers, and core contributions were checked against the 30-report archive through September 8. None of the three deep papers or two Watchlist papers had appeared previously. The audit-instrument Watchlist paper overlaps thematically with recent measurement and fairness briefs, so it is retained as reinforcement rather than promoted as a new implementation signal.

Evidence policy. “Paper Fact” means directly reported by the paper or a verified first-party artifact. “Independent Analysis” is this briefing’s synthesis or calculation. “Enterprise Inference” translates a finding into a bounded future option. “Uncertainty” marks missing generalization, operational, economic, or causal evidence. Benchmark performance is not production readiness. All proposed experiments are isolated, reversible, and non-destructive.

Executive signal

The important control point is where information becomes authority. A stale memory should not become actionable context; a generated test should not become a self-authored excuse for a code change; and a retrieved page should not be mistaken for grounded comprehension. The strongest new research therefore favors validity checks, independence, and failure-stage attribution at system boundaries—not more model autonomy by default.

Three independent research programs converge on that signal. The memory study finds that five popular memory systems fail to enforce revocation consistently and that two systems return revoked records at rank 1 in every tested case; a store-level filter eliminates all 1,620 unsafe actions in those two end-to-end evaluations. ExecCritic shows that a learned test agent can improve a repair agent, but also shows the danger of weak tests: tests from the untrained base model reduce repair performance. CIVI shows that civic search agents gain materially from search on average, yet 72.1% of observed errors remain retrieval-bound and high general benchmark rank only weakly predicts civic-search performance. (Revocation study, ExecCritic, CIVI)

Decision posture. Prototype three control mechanisms: retrieval-time revocation enforcement, independent executable-test contracts, and stage-aware search diagnostics. Prepare the shared foundations—typed provenance, immutable evaluation artifacts, trace ledgers, policy versions, and authoritative-source routing—before broad agent learning or autonomous repair. Do not treat any selected benchmark as a deployment certificate.

Top 3 Future Bets

  1. Revocation-time validity gate — 92.8/100. Why it matters: deleting or superseding a memory is meaningless if retrieval can still grant it authority. Evidence that would change the recommendation: a multi-vendor replication showing that native systems already enforce revocation across indirect insertion, conflicting instructions, and privilege boundaries. Next reversible action: replay a synthetic revoked-record suite against a read-only copy of one retrieval path and compare native behavior with a deterministic pre-context filter.
  2. Independent test-author / test-fix boundary — 89.6/100. Why it matters: executable tests can add useful feedback, but only if repair cannot rewrite the contract and test quality is independently qualified. Evidence that would change the recommendation: no gain—or systematic false confidence—on representative internal repositories after controlling for extra compute and official evaluator leakage. Next reversible action: shadow 50 historical defects with separate test-writer and repair sandboxes; freeze qualified tests and prohibit repair writes to them.
  3. ARISE-style failure-stage diagnostic — 88.9/100. Why it matters: search bypass, bad retrieval, and failure to use a correct source require different fixes. Evidence that would change the recommendation: low inter-rater or causal validity when the diagnostic is repeated on internal tasks and multiple retrieval providers. Next reversible action: label 100 failed search traces using source injection and trace evidence without changing production answers.

Deep paper 1 — Revocation is a retrieval-time security property

Identity and status. Revoked but Still Authoritative: An Empirical Study of Revocation Enforcement in Agent-Memory Systems, Yi Ting Shen, Kentaroh Toyoda, and Alex Leung; submitted September 8, 2026; arXiv:2609.08258; cs.AI/cs.CR; paper licensed CC BY 4.0. The authors released an Apache-2.0 evaluation harness. (paper, artifact)

Contribution and quantitative trace

The paper asks a deceptively simple question: after a policy, credential, consent, or instruction is revoked, will an agent-memory system still retrieve it and induce the model to act on it? It tests five memory systems across nine policy scenarios, nine language models, and six defense conditions. Retrieval uses top-k=10, with ten trials per scenario–model cell at temperature 0.7. The key distinction is between recording revocation and enforcing it before stale state reaches the model.

Claim Directly reported evidence What it establishes What it does not establish
Native revocation enforcement No tested system enforces revocation in every case The failure mode spans multiple memory architectures Market-wide prevalence or a production incident rate
Retrieval persistence Graphiti and experimental mem0 return the revoked record in 81/81 scenario–model cells, always at rank 1 Revoked state can dominate the retrieved context That every deployment configuration behaves identically
Unsafe action Graphiti 358/810 (44.2%); experimental mem0 341/810 (42.1%); pooled 699/1,620 (43.1%) Retrieval exposure translates into substantial action risk in the authored scenarios A portable base rate across enterprises
Store-level filtering 0/1,620 unsafe actions in the two exposed-status systems A deterministic boundary control can dominate prompt-only mitigation in this setup Effectiveness where the system does not expose valid status metadata
Prompt hardening 37.2% unsafe; output filtering 18.1% under an intentionally favorable setup Downstream text controls are weaker than preventing stale context from entering Real-world output filter performance under adversarial adaptation
Model variation 15.0%–60.0% unsafe across nine models; no clean capability-tier relationship Stronger general models are not a substitute for state validity A complete causal explanation for model differences
Explicit prohibition 81.0% unsafe without a prohibition versus 12.9% with one; 4.6% after excluding the reported outlier Explicit rules help, but do not eliminate the systems problem That prompt rules are a sufficient security boundary

The pooled 43.1% figure above is an Independent Analysis calculation from the paper’s two 810-trial counts, not a paper-reported confidence interval. The experimental cells are repeated within common scenarios and prompts; treating all 1,620 trials as independent would overstate precision.

Under indirect insertion, some systems fail before enforcement: Graphiti records revocation in 4/9 scenarios and Zep in 6/9. Other systems either fail to persist status, hide it from retrieval, or provide no enforceable validity field. The proposed guard performs exactly when explicit status is available. Under indirect insertion its results are mixed: it catches only 4/14 unsafe Zep cases in one reported slice and can withhold valid current records. That distinction matters—the strong 0/1,620 result is limited to the systems and conditions where revocation status is exposed correctly.

Methodological critique and prior-work comparison

Strengths include a crossed system–scenario–model design, action-level outcomes rather than retrieval-only proxies, defense comparisons, scenario-level tables, and a public harness. The study also separates memory write, retrieval, and downstream action failures, which makes the control point actionable.

Material limitations remain. The nine scenarios are authored cases rather than a sampled population; pooled uncertainty is not reported; shared prompts and scenarios create within-cell correlation; provider models and hosted memory services can drift; and the guard is given the exact status field that the evaluated system exposes, so its best result is not an independent inference problem. Indirect insertion exposes false withholding and incomplete detection that the headline end-to-end result does not solve. No latency, availability, or organizational policy-authoring study demonstrates production readiness.

Prior work on memory poisoning asks whether attackers can insert malicious state, while provenance systems track where state came from. Version-aware retrieval such as VersionRAG and memory stratification such as MemStrata address state evolution. This paper’s narrower advance is empirical: defender-authored stale state can remain retrievable and authoritative, and enforcement must occur before model context assembly.

Reproducibility and enterprise readiness

The repository includes the evaluation harness, configurations, tests, and result-processing code under Apache-2.0; the paper is CC BY 4.0. Exact replication still requires third-party API credentials, memory backends such as Neo4j, and mutable hosted models. The artifact is credible enough for a local replay, but not a turnkey production control. Enterprise readiness: medium for a deterministic status filter prototype; low-to-medium for general indirect-revocation enforcement. Research Utility Score: 93/100 (rigor 23/25; quantitative traceability 24/25; reproducibility/artifacts 18/20; enterprise relevance 15/15; prior-work advance 13/15).

Deep paper 2 — Tests become useful only when they remain independent

Identity and status. ExecCritic: Learn to Test, Test to Improve for Coding Agents, Leitian Tao and colleagues; submitted September 8, 2026; arXiv:2609.09133; cs.AI/cs.CL/cs.SE; paper licensed CC BY 4.0. Microsoft Research’s Orchard repository is Apache-2.0. (paper, artifact)

Contribution and quantitative trace

ExecCritic separates a Test agent from a Repair agent. A fail-closed harness runs and qualifies the generated test, freezes it, grants the Repair agent write access only to source files, and preserves the benchmark’s official evaluator as the final authority. Both agents use Qwen-3.5-35B-A3B but are trained separately: the Test agent receives supervised training on 5,000 DeepSeek-V4-Flash trajectories and 200 GRPO steps; the Repair agent receives 100 training steps. Training uses SWE-ReBench; evaluation uses SWE-bench Verified.

Evaluation Baseline Generated test Oracle test Interpretable delta
Base Qwen Repair 61.2% 57.3% with base-Qwen tests 69.4% Weak tests hurt by 3.9 points; a correct test offers 8.2 points of headroom
Trained Repair, round 0 vs learned Test agent 68.3% 72.6% 77.6% Learned test adds 4.3 points over the same trained Repair starting point
GPT-5.6, SWE-bench Verified 81.5% 85.7% 89.7% Generated test closes roughly half the displayed oracle gap
GPT-5.6, SWE-bench Pro 61.6% 62.3% 73.4% Small generated-test gain despite large oracle headroom

The Test agent’s Base-to-Gold score rises from 22.2 for the base checkpoint to 39.6 after supervised fine-tuning and 62.2 after reinforcement learning. Reported comparators include Codex-5.3 at 61.0, DeepSeek at 73.4, and GPT-5.6 at 87.8. Cross-language transfer is uneven after Python-focused training: Python 62.2, Rust 66.7, C++ 58.3, C 26.1, and Java 2.4. That is a warning against treating the method as language-agnostic.

The Pro result clarifies the bottleneck. Its median/mean failed-to-pass test counts are 3/14.43 versus 1/3.03 on Verified, so one fixed generated test covers less of a broader specification. The paper reports three repair runs with fixed test bundles. In a 120-trajectory analysis, repair takes a mean 13 turns, median 11, 75th percentile about 17, and 90th percentile 34. The paper does not give end-to-end token, wall-clock, or dollar cost, so the incremental performance cannot yet be converted into enterprise economics.

Methodological critique and prior-work comparison

The study’s strongest design choice is permission separation: test authoring, repair, and official verification are distinct. It also tests negative transfer—the untrained generated test makes repair worse—rather than reporting only a successful learned critic. Cross-language and harder-benchmark results expose real boundaries.

Limitations include one fixed generated test per issue, possible semantic errors in the generated tests, gains confounded with extra inference and training compute, no interaction-level confidence intervals or significance tests in the headline comparisons, and a single model family for learned policies. Jointly trained Test and Repair agents could collude or overfit if independence is weakened. The repository contains code and launchers, but not the exact training trajectories, model checkpoints, benchmark environments, results, or credentials, limiting exact reproduction.

Compared with fixed benchmark tests, ExecCritic creates issue-specific executable feedback. Compared with self-refinement approaches that let one agent inspect and rewrite everything, it treats tests as a separate contract. Compared with evolving-test methods, one frozen test reduces collusion but also under-covers multi-faceted tasks. The enterprise lesson is therefore the boundary design—not an assumption that this particular policy should be deployed.

Reproducibility and enterprise readiness

The public Apache-2.0 repository is a useful scaffold and the paper provides detailed training recipes, but the release is young and externally unreplicated. Production use would require repository isolation, secret handling, deterministic sandboxes, test-flakiness controls, cost accounting, and an official human- or system-owned acceptance suite. Enterprise readiness: medium for shadow testing on historical defects; low-to-medium for autonomous repair. Research Utility Score: 91/100 (rigor 22/25; quantitative traceability 23/25; reproducibility/artifacts 17/20; enterprise relevance 15/15; prior-work advance 14/15).

Deep paper 3 — Diagnose search failures before changing the model

Identity and status. CIVI: A Framework for Diagnosing Search Agent Failures in Civic Information, Dingying Liu, Yunshun Zhong, Wentao Zhang, and Yiyuan Li; submitted September 8, 2026; arXiv:2609.08094; cs.AI; paper licensed CC BY 4.0. The code is MIT-licensed and the dataset README declares CC BY 4.0. (paper, code, dataset)

Contribution and quantitative trace

CIVI contains 4,097 expert-verified multiple-choice questions derived from 576 public-sector pages across the United States, Canada, and Australia; federal, state/provincial, and local levels; and four UN COFOG functions. Two annotators review every question: raw agreement is 96.8%, and 94.1% of generated items are accepted. Ten frontier search agents receive at most three search rounds and ten URLs through a common Exa retrieval substrate.

Finding Reported result Decision meaning
Human reference Five people × 150 stratified questions; 92.67% mean, SD 3.1 points Useful ceiling estimate, but too small for a universal human benchmark
Best agent Gemini 3.1 Pro 78.28% ±1.3; 14.4 points below overall human result, 15.3 on matched subset A material gap remains in source-grounded civic tasks
Jurisdiction effect Mean accuracy 65.6% federal, 62.6% state, 56.7% local Local information is systematically harder in this corpus
Search value Agentic search averages +10.0 points over disabled and +9.1 over one-shot RAG Iterative retrieval helps on average
Search inconsistency Invocation ranges 13.5%–99.8% across models “Has tools” does not mean “uses tools when needed”
Failure attribution 34.5% search bypass + 37.6% retrieval failure = 72.1% retrieval-bound Most observed errors call for routing/retrieval controls before model replacement
Benchmark transfer Spearman ρ=.27, p=.45, N=10; Kendall τ=.24, p=.38 General leaderboard position is not a reliable selection rule here

The model-level table is non-monotonic. GPT-5.4 rises from 60.4% with search disabled and 61.9% with one-shot RAG to 72.88% agentic. Gemini 3 Flash falls from 66.5% disabled to 62.44% agentic, despite 54.2% one-shot RAG. Mistral improves from 32.0% disabled to 55.33% agentic, while its RAG score is 50.6%. These differences argue for policy-and-model evaluation as a unit rather than a model-only procurement score.

ARISE combines trace evidence with authoritative-source injection to assign every error to search bypass, retrieval failure, or comprehension. Only 2.3%–4.8% of each model’s failures persist after the gold page is injected, even though the median page is roughly 1,000 words. Source injection is a diagnostic intervention: it indicates what would have happened with the selected authoritative page in context, not what a production retriever will reliably find.

Methodological critique and prior-work comparison

Strengths include cross-national and jurisdictional coverage, a common search-provider substrate, explicit baselines, source-level validation, model-level tables, human reference performance, and a taxonomy grounded in traces rather than answer correctness alone.

The benchmark is English-only and covers three democracies; legal, language, and source ecosystems elsewhere may differ. A single Exa substrate improves comparability but limits ecological validity. The human baseline is only five people and 150 questions each. Public web pages and hosted models drift, and the source-text SQLite corpora used for exact runs are not distributed, though the code can rebuild them. Source injection can localize failure but does not prove that a proposed routing fix will cause a production improvement. Model rankings should be treated as dated observations, not durable vendor claims.

Earlier public-sector QA datasets are typically single-country, single-jurisdiction, or answer-only. CIVI’s useful advance is to combine cross-national hierarchy with an explicit failure-stage diagnostic. For enterprise knowledge systems, the analogous move is to separate query-policy failure, authoritative-source discovery, content extraction, and comprehension rather than collapsing all errors into “RAG quality.”

Reproducibility and enterprise readiness

The code and dataset licenses are explicit and the repository includes evaluation, prompts, and configuration. Exact numerical reproduction depends on mutable pages, models, and APIs; not all source snapshots are distributed. The framework is ready to adapt as an offline diagnostic but not validated as an online causal repair system. Enterprise readiness: medium for a trace-labeling benchmark; low-to-medium for automated routing changes. Research Utility Score: 90/100 (rigor 22/25; quantitative traceability 24/25; reproducibility/artifacts 16/20; enterprise relevance 14/15; prior-work advance 14/15).

Watchlist

Reasoning representations may change human error detection—but the study is narrow

Do Reasoning Representations Help Humans Evaluate LLM Outputs? studies six explanation formats across three benchmarks using GPT-5 traces. Of 140 candidate problems, 27 all-correct items are retained; researchers inject 42 error traces. Sixty-four people start and 51 finish; the analytic sample is 50. Zero-shot chain-of-thought has the lowest false-alarm rate (7.7%) and highest error localization (95.5%), while the most preferred format, Plan-and-Solve (26% preference), has 19.2% false alarms and 57.1% localization. Structural agreement is low: Krippendorff’s alpha is .11–.37 for key-step selection and .05–.48 for support judgments. (paper)

Why Watchlist. The result usefully separates preference from diagnostic utility, but the study uses one model, a convenience sample from one institution, synthetically injected errors, an all-correct filter that retains only 19.3% of candidates, and prompt conditions that change both reasoning content and presentation. The main tables do not establish generalizable inferential differences, and no public study artifact was verified. Monitor for preregistered, multi-model, task-realistic replications. Research Utility Score: 74/100 (rigor 18; traceability 20; artifacts 8; enterprise relevance 14; advance 14).

Audit instruments can dominate measured demographic effects

The Audit Decides the Verdict: Instrument Effects Rival Demographic Bias in LLM Decision Audits reports 40,726 model requests across five models, three decision domains, 40 name pairs, and rating, decide, and rank instruments. None of 36 preregistered primary contrasts survives Benjamini–Hochberg correction; none of 12 interactions is nonzero. A 12,000-slot precision extension estimates the hiring-ranking effect at +.008 with a 95% interval of [−.044, .060] and supports an equivalence bound below .052 against a .067 margin (p=.013). First-position effects are comparable to or larger than observed demographic effects. The authors also disclose and repair an accidental composition confound in a wording arm. (paper, project)

Why Watchlist. The statistical design is stronger than typical audit papers, but the finding overlaps the archive’s recent evaluation-instrument and procedural-fairness themes. Names are the only demographic signal; profiles are synthetic; served models differ; and equivalence is established only for one bounded hiring-ranking comparison—not as a fairness certificate for lending, triage, or production decisions. Treat it as knowledge reinforcement and an argument for versioned audit instruments, not a production conclusion. Research Utility Score: 86/100 (rigor 24; traceability 24; artifacts 15; enterprise relevance 12; advance 11).

Cross-paper synthesis

The papers address different systems—memory, code repair, and civic search—but their failure structures align:

  1. State can be present but invalid. The memory system retrieves a record whose authority has expired.
  2. Feedback can be executable but wrong. A weak generated test actively reduces repair quality.
  3. Evidence can be accessible but unused. Search-capable agents bypass search or retrieve the wrong source.
  4. A downstream score hides the failure stage. Endpoint accuracy alone cannot tell whether the fix belongs in storage, routing, retrieval, comprehension, testing, or model choice.
  5. The most reusable controls are architectural. Status metadata, immutable artifacts, permission separation, trace ledgers, authoritative-source registries, and independent evaluation can span models and vendors.

Independent Analysis. These results support a “boundary contract” model for enterprise AI. Every artifact crossing a component boundary should carry identity, provenance, validity interval, policy version, authority, and evaluation status. The receiving component should fail closed when a required field is missing or invalid. That will not solve semantic judgment, but it narrows the set of failures delegated to probabilistic models.

Prototype Soon

1. Revocation-time validity gate — 92.8/100

  • Category: Memory & Context / Safety & Governance / AI Security.
  • Research signal and support: Paper Fact — Graphiti and experimental mem0 returned revoked records in all 81/81 cells, and a store-level filter reduced unsafe actions from 699/1,620 pooled to 0/1,620 where explicit status was exposed. Supports: Revocation study.
  • Problem or opportunity: Deleted, expired, superseded, or consent-withdrawn state may remain technically retrievable and become authoritative model context.
  • Proposed capability: Enterprise Inference — a deterministic pre-context gate evaluates record identity, status, policy version, validity interval, subject consent, and requester authorization. It excludes invalid records, logs the decision, and sends ambiguous cases to quarantine rather than to the model.
  • Placement: retrieval/knowledge, agent layer, security/governance, observability.
  • Business value: risk reduction, reliability, quality, customer trust. Technical value: makes revocation enforceable at the last deterministic boundary before probabilistic reasoning.
  • Maturity/readiness: Strong authored benchmark plus public harness; directly prototypable when metadata exists. Indirect-insertion results are incomplete. Confidence: High for exposed-status filtering; Moderate for general revocation. Horizon: Now. Effort: M.
  • Dependencies: canonical record IDs; lifecycle schema; policy-version ledger; identity and authorization; audit events; quarantine and human override.
  • Risks: missing or forged status, false withholding, split-brain stores, race conditions, privacy leakage in logs, emergency-access conflicts, operational bypass, user confusion after legitimate recall.
  • Build / Buy / Partner: Build the policy gate and logs because they encode enterprise authority; buy or partner for storage adapters and policy engines only after conformance tests.
  • Minimum reversible experiment: Read-only replay of synthetic active/revoked/conflicting records against one copied index; compare native retrieval, prompt hardening, and pre-context filtering without executing tools.
  • Success metrics / stop conditions: zero revoked records delivered in the test corpus; ≥99.5% valid-record recall; complete decision provenance; bounded p95 overhead. Stop if valid recall drops below the predeclared threshold, metadata coverage is insufficient, or bypass routes remain unobservable.
  • Roadmap trigger: two heterogeneous stores pass indirect-insertion, concurrency, and privilege-boundary tests; security and privacy owners approve the lifecycle schema; internal incident and latency budgets are defined.

2. Independent test-author / test-fix boundary — 89.6/100

  • Category: AI Software Engineering / Agentic AI / Evaluation & Observability.
  • Research signal and support: Paper Fact — learned tests raise a trained Repair agent from 68.3% to 72.6% on SWE-bench Verified, while untrained base-model tests lower repair from 61.2% to 57.3%. Supports: ExecCritic.
  • Problem or opportunity: Coding agents can optimize to weak or self-modified tests, creating apparent success without satisfying the real requirement.
  • Proposed capability: Enterprise Inference — run test authoring in an isolated role, qualify the test in a fail-closed sandbox, freeze its hash, deny the repair process write access to tests, and require an independently owned acceptance suite before promotion.
  • Placement: developer platform, orchestration, evaluation, security/governance.
  • Business value: productivity, quality, speed, reliability, risk reduction. Technical value: converts ambiguous natural-language issues into executable evidence while reducing evaluator–actor collusion.
  • Maturity/readiness: Strong benchmark signal and code scaffold; limited language transfer and missing cost evidence. Confidence: Moderate. Horizon: Now. Effort: L.
  • Dependencies: hermetic build/test sandbox; repository ACLs; flaky-test detector; secret isolation; official evaluation suite; patch provenance; compute and token telemetry.
  • Risks: generated tests encode the wrong requirement, repository poisoning, test leakage, nondeterminism, high cost, long repair loops, language underperformance, false confidence from a single passing test.
  • Build / Buy / Partner: Build the permission boundary and evidence registry; buy commodity sandboxes; partner only for language-specific test generation where internal expertise is absent.
  • Minimum reversible experiment: Re-run 50 resolved internal defects with a test-only agent and a source-only repair agent. Freeze qualified tests, keep outputs off production branches, and compare against the same repair budget without generated tests.
  • Success metrics / stop conditions: official-suite resolution lift; precision of generated tests against human requirements; flaky-test rate; changed-file policy violations; cost per valid fix; reviewer time. Stop if official-suite regressions rise, semantic-test precision is below 90%, or cost-adjusted lift is non-positive.
  • Roadmap trigger: statistically credible lift on at least two internal languages and repository types, no security boundary violations, and positive reviewer-time economics under a fixed compute budget.

3. ARISE-style failure-stage diagnostic — 88.9/100

  • Category: RAG & Knowledge / Evaluation & Observability.
  • Research signal and support: Paper Fact — CIVI attributes 34.5% of errors to search bypass and 37.6% to retrieval failure; only 2.3%–4.8% of each model’s failures remain after authoritative-source injection. Supports: CIVI.
  • Problem or opportunity: Endpoint accuracy cannot tell teams whether to change routing, retrieval, source policy, context construction, comprehension, or the model.
  • Proposed capability: Enterprise Inference — a diagnostic replay service injects a verified gold source into failed traces, compares behavior, and assigns failure stage with evidence links. It informs remediation but never alters production answers automatically.
  • Placement: evaluation, observability, retrieval/knowledge, human-review layer.
  • Business value: speed, cost, quality, reliability. Technical value: reduces blind model swapping and makes retrieval investments falsifiable.
  • Maturity/readiness: Detailed benchmark and public code/dataset; source injection is diagnostic rather than causal deployment evidence. Confidence: High for offline triage, Moderate for remediation choice. Horizon: Now. Effort: M.
  • Dependencies: representative failure corpus; source-of-truth owners; trace capture; authoritative-source labels; privacy-safe replay; adjudication rubric.
  • Risks: gold-source leakage, hindsight bias, ambiguous multi-source answers, evaluator disagreement, sensitive trace retention, false causal attribution, web drift.
  • Build / Buy / Partner: Build the domain taxonomy and gold-source registry; buy trace infrastructure if it preserves exportable event identity.
  • Minimum reversible experiment: Label 100 historical failed queries with original traces and injected approved sources; double-review 20% and make no runtime policy changes.
  • Success metrics / stop conditions: ≥0.8 adjudicator agreement; ≥90% failures assigned with evidence; remediation recommendations predict held-out replay gains. Stop if categories are unstable or source injection changes the task definition.
  • Roadmap trigger: failure labels remain stable across two retrievers and two model families and lead to a predeclared improvement in a held-out replay set.

Prepare Foundations

4. Typed memory lifecycle metadata — 87.2/100

  • Category: Memory & Context / Data & Knowledge Infrastructure.
  • Research signal and support: Paper Fact — the revocation guard is exact where a system exposes trustworthy active/revoked status and incomplete where status is not recorded or surfaced. Supports: Revocation study.
  • Problem or opportunity: Memory stores often preserve content and embeddings while omitting enforceable lifecycle, authority, and supersession semantics.
  • Proposed capability: Enterprise Inference — a shared schema for record ID, lineage, author, authority, validity interval, supersedes/superseded-by, consent, classification, policy version, and deletion receipt; indexes inherit rather than recreate these facts.
  • Placement: data platform, retrieval/knowledge, security/governance.
  • Business value: reliability, risk reduction, quality. Technical value: enables revocation gates, rebuilds, provenance audits, and model-independent migration.
  • Maturity/readiness: The need is strongly supported; no cross-vendor schema standard is established. Confidence: High on need, Moderate on design. Horizon: 3–6 months. Effort: L.
  • Dependencies: data governance ownership; system inventory; canonical identity; retention and consent policy; schema registry; adapter strategy.
  • Risks: metadata drift, conflicting authorities, legacy gaps, high migration cost, privacy exposure, performance overhead, false finality in distributed deletion.
  • Build / Buy / Partner: Build the canonical schema and conformance suite; partner with vendors on adapters.
  • Minimum reversible experiment: Map 1,000 synthetic or non-sensitive records from two stores into the schema and test active, expired, superseded, and revoked resolution without migrating production data.
  • Success metrics / stop conditions: ≥99% deterministic lifecycle resolution; full lineage for all test records; no unauthorized metadata exposure. Stop if core stores cannot surface stable IDs or deletion receipts.
  • Roadmap trigger: two materially different stores pass conformance and governance approves the authority-resolution rules.

5. Authoritative-source routing policy — 86.3/100

  • Category: RAG & Knowledge / Data & Knowledge Infrastructure.
  • Research signal and support: Paper Fact — CIVI reports average agentic-search gains but 13.5%–99.8% search invocation and large local-jurisdiction degradation. Supports: CIVI.
  • Problem or opportunity: General web retrieval treats official, current, local, and jurisdiction-appropriate sources as ranking hints rather than explicit policy constraints.
  • Proposed capability: Enterprise Inference — route queries using domain, jurisdiction, freshness, and authority requirements; maintain approved source registries and require provenance-aware fallback when authoritative coverage is absent.
  • Placement: orchestration, retrieval/knowledge, model gateway, security/governance.
  • Business value: quality, customer experience, risk reduction, speed. Technical value: turns source authority into a testable retrieval objective.
  • Maturity/readiness: Search benefits and failure heterogeneity are well demonstrated in one civic benchmark; transfer is unproven. Confidence: Moderate. Horizon: 3–6 months. Effort: M.
  • Dependencies: domain taxonomy; source owners; freshness SLAs; jurisdiction metadata; crawl/index permissions; citation and provenance support.
  • Risks: source capture, stale official pages, missing local sources, accessibility failures, regional legal differences, latency, policy overconstraint.
  • Build / Buy / Partner: Build authority rules and registries; buy underlying search; partner with domain source owners for access and freshness.
  • Minimum reversible experiment: Replay 200 internal knowledge questions using current retrieval and an authority-constrained route, judged blind by domain owners.
  • Success metrics / stop conditions: authoritative-hit rate, supported-answer accuracy, abstention quality, freshness, latency and cost. Stop if authority constraints reduce answer accuracy or coverage without a compensating risk benefit.
  • Roadmap trigger: held-out improvement survives two retrieval providers and domain owners accept the abstention/fallback policy.

6. Executable behavior-contract registry — 84.9/100

  • Category: Evaluation & Observability / AI Software Engineering / Safety & Governance.
  • Research signal and support: Independent Analysis — frozen generated tests in ExecCritic and retrieval validity rules in the revocation study are both executable contracts whose identity and immutability determine trust.
  • Problem or opportunity: Prompts, policies, tests, and evaluators change independently, making it difficult to know which contract authorized a result.
  • Proposed capability: Version, hash, sign, and bind tests, policy rules, prompts, schemas, evaluators, and acceptance thresholds to each trace. Promotion requires an independent contract owner.
  • Placement: developer platform, evaluation, security/governance, observability.
  • Business value: reliability, quality, speed, risk reduction. Technical value: supports deterministic replay and prevents silent evaluator drift.
  • Maturity/readiness: Built from convergent evidence but not evaluated as one platform. Confidence: Moderate. Horizon: 3–6 months. Effort: L.
  • Dependencies: artifact registry; identity and signing; change management; lineage graph; evaluator ownership; replay infrastructure.
  • Risks: registry becomes procedural overhead, signatures without semantic review, stale contracts, owner bottlenecks, sensitive test exposure.
  • Build / Buy / Partner: Build the contract model and ownership rules; buy artifact storage/signing where standards-based.
  • Minimum reversible experiment: Register and replay one model evaluation, one retrieval policy, and one code test suite with immutable hashes and documented owners.
  • Success metrics / stop conditions: 100% trace-to-contract resolution; reproducible replay within tolerances; change-review latency. Stop if the system cannot distinguish semantic from cosmetic changes or imposes disproportionate delivery delay.
  • Roadmap trigger: three teams independently reproduce historical decisions and audit owners accept the promotion workflow.

7. Audit-instrument versioning and planted controls — 82.0/100

  • Category: Evaluation & Observability / Safety & Governance.
  • Research signal and support: Paper Fact — the Watchlist audit finds no corrected primary demographic effects in its tested conditions while instrument order effects are comparable or larger; it uses planted controls and equivalence bounds. Supports: Audit Decides the Verdict.
  • Problem or opportunity: Changes in prompt form, response scale, item order, or decision framing can be misread as model or demographic effects.
  • Proposed capability: Enterprise Inference — version every audit instrument; randomize order; include positive, negative, and position controls; prespecify correction and equivalence margins; retain raw outputs for re-analysis.
  • Placement: evaluation, observability, human-review layer, security/governance.
  • Business value: quality, risk reduction, reliability. Technical value: makes evaluation-instrument variance measurable rather than hidden.
  • Maturity/readiness: Statistically strong single study with synthetic profiles and bounded claims. Confidence: Moderate. Horizon: 3–6 months. Effort: M.
  • Dependencies: audit governance; statistical review; instrument registry; randomization; privacy review; immutable raw-output store.
  • Risks: planted controls leak, multiple-testing misuse, equivalence margins chosen post hoc, synthetic audits overgeneralized, sensitive attribute handling.
  • Build / Buy / Partner: Build governance and prespecification; partner with domain and fairness experts for design review.
  • Minimum reversible experiment: Re-run a fixed internal audit corpus under rating, decision, and rank formats with randomized position and preregistered analysis.
  • Success metrics / stop conditions: instrument variance, control recovery, confidence-interval width, reproducibility. Stop if results are too underpowered for the stated decision or raw data cannot be governed safely.
  • Roadmap trigger: instrument effects are material or a stable effect survives correction, replication, and domain review.

Monitor for Maturity

8. Human reasoning-display calibration harness — 73.7/100

  • Category: Human-AI Workflow / Evaluation & Observability.
  • Research signal and support: Paper Fact — zero-shot chain-of-thought has 7.7% false alarms and 95.5% localization in the Watchlist study, while the most preferred Plan-and-Solve format performs worse on both measures. Supports: Reasoning Representations.
  • Problem or opportunity: Interfaces optimize explanation readability or preference without measuring whether humans detect and localize consequential errors.
  • Proposed capability: Enterprise Inference — test multiple evidence presentations using task-specific seeded errors, measuring detection, localization, reliance, time, and downstream decisions; expose only formats that improve calibrated oversight.
  • Placement: applications, human-review layer, evaluation.
  • Business value: quality, productivity, customer experience, risk reduction. Technical value: separates interface preference from supervisory effectiveness.
  • Maturity/readiness: One small, synthetic, single-model study; no verified artifact. Confidence: Low-to-Moderate. Horizon: 6–12 months. Effort: M.
  • Dependencies: representative tasks; reviewer population; ethical study design; error-seeding process; accessibility support; decision-impact metrics.
  • Risks: reasoning traces are unfaithful, sensitive internals exposed, cognitive overload, automation bias, adversarially persuasive explanations, nonrepresentative users.
  • Build / Buy / Partner: Build a small internal harness; partner with human-factors researchers for high-stakes domains.
  • Minimum reversible experiment: Within-subject study with 30–50 representative reviewers on historical, non-live cases and prevalidated error seeds.
  • Success metrics / stop conditions: false alarms, miss rate, localization, decision quality, time and calibrated reliance. Stop if no format improves decision quality or if exposure creates security/privacy risk.
  • Roadmap trigger: replicated improvement on realistic errors across at least two workflows and reviewer groups.

Deprioritize for Now

9. Self-certifying autonomous repair loop — 64.2/100

  • Category: Agentic AI / AI Software Engineering.
  • Research signal and support: Paper Fact + Uncertainty — weak self-generated tests reduce repair performance, generated tests leave large oracle headroom on SWE-bench Pro, and language transfer falls to 2.4 on Java. Supports: ExecCritic.
  • Problem or opportunity: Full autonomy promises speed, but letting one agent write the code, define success, and approve promotion collapses independence.
  • Proposed capability: No production capability recommended. Keep any joint test-and-repair learner confined to research sandboxes with an external evaluator and no merge rights.
  • Placement: isolated experiment infrastructure only.
  • Business value: possible future speed; currently outweighed by reliability and security risk. Technical value: research on joint optimization, not a deployable control.
  • Maturity/readiness: Low; benchmark-only, incomplete cross-language generalization, missing economics, collusion risk. Confidence: High that production promotion is premature. Horizon: 12+ months. Effort: XL.
  • Dependencies: independent hidden suite; formal permissions; adversarial test generation; strong sandboxing; economic evidence; human acceptance owner.
  • Risks: evaluator gaming, test collusion, malicious patches, repository exfiltration, hidden regressions, escalating compute, accountability gaps.
  • Build / Buy / Partner: Do not buy or deploy. Maintain a small internal research track only if strategically relevant.
  • Minimum reversible experiment: Synthetic repository challenge where the external evaluator deliberately includes hidden anti-collusion and security cases; outputs cannot leave the sandbox.
  • Success metrics / stop conditions: zero permission breaches; improvement on independently held-out tasks; no reduction in semantic-test precision; bounded cost. Stop at any evaluator tampering, hidden regression, or negative cost-adjusted lift.
  • Roadmap trigger: multi-organization replication across languages, independent hidden-evaluator gains, demonstrated non-collusion, clear liability ownership, and positive total-cost evidence.

Enterprise AI Architecture Implications

Independent Analysis — 12–24 month view. The reviewed signals favor an enterprise AI architecture with a model-independent evidence and authority control plane. The model gateway remains useful for routing and cost, but durable reliability shifts toward typed artifacts and enforceable boundaries around it.

Applications / human review
          │ explanations, appeals, approvals
          ▼
Agent orchestration ──────────────── model gateway + cost telemetry
          │                                      │
          ├── executable contract registry       ├── model/version identity
          ├── permission-separated roles         └── serving-contract checks
          │
          ▼
Context & knowledge plane
  ├── canonical record identity and provenance
  ├── lifecycle / consent / revocation service
  ├── authoritative-source registry
  └── pre-context validity and authorization gate
          │
          ▼
Evaluation & observability plane
  ├── immutable typed traces
  ├── failure-stage attribution and replay
  ├── independent verifier / test sandbox
  ├── audit-instrument registry and planted controls
  └── outcome, latency, cost and human-override telemetry

Shared foundations unlock multiple enhancements:

  • Identity and authorization: record, user, agent, model, test, evaluator, and policy identities must be stable across handoffs.
  • Data provenance and lifecycle: raw content, derived embeddings, supersession links, validity intervals, consent, and deletion receipts should remain connected.
  • Policy enforcement: deterministic gates should block invalid context and unauthorized actions before probabilistic reasoning.
  • Evaluation infrastructure: immutable test bundles, gold-source replay, hidden official evaluators, and instrument versions make decisions reproducible.
  • Observability: proposed, retrieved, delivered, executed, rejected, and human-overridden artifacts should be distinct events.
  • Human-review controls: ambiguous revocation, conflicting authority, high-impact repair, and unsupported answers require accountable escalation and appeal.
  • Experiment infrastructure: reversible shadow traffic, historical replay, variant registries, cost telemetry, and stop conditions let evidence mature without production side effects.

No current enterprise stack, vendor, data platform, or security maturity is assumed. Before any roadmap decision, internal context is required on regulated data, authorization models, incident tolerance, repository languages, search domains, latency and cost budgets, human-review capacity, and existing provenance coverage.

Implementation priorities

Now — run three isolated diagnostics

  1. Replay revoked records with and without a deterministic pre-context gate.
  2. Shadow historical defects with separated test-author and repair roles under a fixed compute budget.
  3. Relabel failed search traces by bypass, retrieval, and comprehension using verified source injection.

Next — build shared foundations

  1. Define canonical IDs and lifecycle metadata for memories, sources, tests, policies, and evaluators.
  2. Add immutable hashes, ownership, and version bindings to every evaluation trace.
  3. Establish authoritative-source registries and privacy-safe replay stores.
  4. Record cost, latency, override, abstention, and incident telemetry alongside quality.

Later — expand only after triggers

Move from replay to limited shadow traffic only when the stated metrics and stop conditions are met. Allow production side effects only after independent validation, threat modeling, privacy and security review, rollback testing, human accountability, and representative internal economics. Do not promote joint self-certifying agents merely because a public benchmark improves.
