Paper Fact · New preprint

Git4Data: Database-Native Version Control for AI Agents

Hongshen Gou et al. · submitted September 2, 2026

Technical thesis. Snapshot, tag, branch, diff and merge can be implemented as database-native primitives over immutable object storage and MVCC, making agent data changes cheap, isolated and reversible.

Verified evidence. In the reported SF100 primary-key clone case, Git4Data completed in 0.20 seconds, versus 114.6 seconds and approximately 34 GB for a materialized copy. The performance case is strongest for sparse changes and compatible workloads; it does not prove universal superiority across database engines or production governance conditions.

Enterprise inference. Place a versioned data sandbox between agent orchestration and mutable enterprise data. Require branch-per-task isolation, typed diffs, identity-bound merge authorization, retention controls and rollback evidence.

Minimum reversible experiment. Replay 25 read/write workflows against a disposable database clone. Measure branch creation latency, storage growth, merge conflicts, rollback time and unauthorized writes. Stop on any production connection, data leakage or irrecoverable merge.

Coverage, Not Targeting: Rethinking Process Credit Assignment

Reasoning, verification and reinforcement learning

Technical thesis. The value of process supervision depends less on locating one supposedly pivotal step than on how much of the causal trajectory has reliable verification coverage.

Verified evidence. Uniform dense credit improved held-out assertion support by 0.079 over binary outcome reward in the reported comparison, with one-sided p=.003 and a 95% confidence interval from +.009 to +.149. Targeted treatment did not dominate when verifier density was low.

Independent critique. This is evidence about the studied update regime, verifier construction and task distribution—not a blanket result that uniform credit is always optimal. Coverage estimates can themselves be biased when the verifier misses important causal steps.

Enterprise inference. Add verifier-coverage telemetry before adopting process-reward optimization. Track what fraction of consequential decisions, tool calls and state changes have trustworthy per-step checks.

Minimum reversible experiment. On a historical agent dataset, compare endpoint-only, targeted-step and uniform-trace scoring using held-out human labels. Stop if process scoring worsens final-task accuracy or concentrates rewards on unverified steps.

Paper Fact · New preprint

From Tokens to Semantics: Hybrid Hallucination Detection

Uncertainty monitoring and semantic verification

Technical thesis. Token-level confidence signals and semantic disagreement reveal partly different failure modes; a hybrid detector can improve triage, but no detector fully resolves confident falsehoods.

Verified evidence. Token-signal families led 121 of 148 reported ablations, while semantic disagreement provided complementary coverage. Exact transfer to proprietary enterprise domains remains unverified.

Enterprise inference. Use a calibrated triage layer combining model-native uncertainty, semantic cross-checks and domain evidence. Treat the output as a review-routing signal—not proof of factuality.

Minimum reversible experiment. Score 300 labeled internal outputs across routine, ambiguous and adversarial cases. Compare token-only, semantic-only and hybrid methods on precision-recall, calibration, reviewer workload and missed high-severity errors. Stop if the detector creates false confidence or increases review burden without reducing severe misses.

Enterprise AI Architecture Implications

12–24 month direction; stack-agnostic.

Applications & agents
→
Orchestration + typed traces
→
Versioned state + policy gate
→
Evaluation + human promotion

Execution and promotion should be separate. Agents propose work; orchestration emits causal traces; a versioned state service holds isolated branches; identity and policy constrain reads, writes and merges; the model gateway captures uncertainty signals; evaluation estimates verifier coverage and calibrated risk; observability joins actions to diffs, cost and outcomes; human review authorizes promotion.

Internal context required before implementation: workflow criticality, data sensitivity, database compatibility, model/log-probability access, reviewer capacity, regulatory duties, incident history, cost envelope and risk appetite.

  2. Define trace, branch, authorization and promotion schemas.

  5. Require rollback, cost and human-review capacity thresholds.
